// key test
キーボードを押すと、このツールのキーマップ上で押したキーが光ります（書き込み後の動作確認用）
表示中のレイヤー待機中
押している 確認済み 未確認 PC に信号が出ないキー（レイヤー切替・LED・感度など） ▽ 下のレイヤーと同じ
入力の記録最新が上

      
・左の USB をつないでいるときは QWERTY 配列、右の USB をつないでいるときは大西配列のキーテストを開いてください（つないだ側のキーマップで動きます）。

      ・この画面を開いている間はキーの入力を横取りします（Tab や F キーもブラウザでは動きません）。ただし Win キーや Ctrl+Alt+Del など OS が先に使う組み合わせは止められません。

      ・ブラウザに届くのは「どの文字が入力されたか」だけで、キーボード内のレイヤーは見えません。表示のレイヤーは、届いたキーから推測しています（例: F1 が来たら L2、ボールを動かしたら L4）。違う場合はタブで手動で切り替えてください。

      ・かな／英数キーは OS や IME の設定によってはブラウザに届きません。

    

  







  

    
// github build

    
今の設定のファイルをフォークに push し、GitHub Actions で QWERTY 用・大西用の .hex をビルドします

  


  

    
接続設定GitHub API

    

      

        
リポジトリ
自分のフォーク（owner/name）

        

      

      

        
ブランチ
keymaps/ の albion（共通）・albion_qwerty・albion_onishi に置きます

        

      

      

        
アクセストークン
Fine-grained token（下の説明を参照）

        

      

      

        
トークンを保存
このブラウザ・この開き方（公開 URL か手元のファイルか）ごとに保存。共用 PC では OFF

        

      

      

        アクセストークンの作り方（最初の1回だけ）
        
    
          
  1. GitHub 右上のアイコン → Settings → 一番下の Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。
    2. 
          
  2. 名前は「keyball61設定変更ツール」など。期限は好みで（切れたら作り直し）。
    3. 
          
  3. Repository access は Only select repositories で keyball だけを選ぶ。
    4. 
          
  4. Permissions の Repository permissions で Contents: Read and write と Actions: Read and write を設定。
    5. 
          
  5. Generate token で表示された github_pat_... を上の欄に貼る（画面を閉じると二度と表示されません）。
    6. 
        

      

    

  


  

    
push してビルドbuild-user.yml

    

      
    
        
  1. どれをビルドするかを選びます。この画面を開くと GitHub と見比べて、変えた側を自動で選んでおきます。
    2. 
        
  2. 共通設定（トラックボール・自動マウスレイヤー・機能スイッチ）を変えたときは両方に効くので、「両方」しか選べません。
    3. 
        
  3. 「push してビルド開始」を押すと、選んだ側と共通の変更だけをフォークに上げてビルドを始めます（選ばなかった側の変更は上げません）。
    4. 
        
  4. ビルドには数分かかります。終わるとこの下に Actions の画面へのリンクが出ます。リンク先の Artifacts から keyball61-albion_qwerty-firmware（左用）・keyball61-albion_onishi-firmware（右用）をダウンロードし、zip を展開します。
    5. 
        
  5. 中の .hex を「書き込み (.hex)」画面の左用・右用の欄にそれぞれドラッグして書き込みます。
    6. 
      

      

        
        
        
      

      
GitHub と見比べるには「変更を確認」を押してください。

      

        
        
        
        
      

      

      

    

  







  

    
// flash

    
ビルドした .hex を Pro Micro (Caterina) にブラウザから書き込みます（QMK Toolbox の代わり）

  


  

    このブラウザは Web Serial に対応していないため書き込めません。Chrome か Edge で開いてください。
  


  

    
書き込みの手順Web Serial / AVR109

    

      
    
        
  1. 左には QWERTY 用（albion_qwerty）、右には大西用（albion_onishi）の .hex を、下の欄にそれぞれ入れます。ファイル名が欄と合わないときは書き込みを止めます。
    2. 
        
  2. 書き込む側（左 or 右）の USB ケーブルだけをパソコンにつなぎます。左右をつなぐケーブル（TRRS）は、USB を抜いた状態で抜き差ししてください。
    3. 
        
  3. その側の「書き込む」を押すと、ポート選択の画面が開きます。
    4. 
        
  4. 画面が開いた状態でキーボードをブートローダーモードにします。L3 の Boot キー（かな長押し＋左下 or 右下）を押すか、基板のリセットボタンを押します（反応しない場合は素早く2回）。
    5. 
        
  5. 一覧に「Arduino Leonardo」「SparkFun Pro Micro」「USB シリアル デバイス」などが出たら、約 8 秒以内に選んで「接続」を押します。
    6. 
        
  6. 書き込みと確認（読み戻し）が終わると、キーボードが自動で再起動します。もう片方も、ケーブルをつなぎ替えて同じ手順で書き込みます。
    7.
